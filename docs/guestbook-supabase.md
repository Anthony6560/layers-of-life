# 回声留言簿：Supabase 配置

网站的留言入口已经接入前端，但发布包默认关闭数据库连接。要让游客真正提交和读取留言，需要创建一个 Supabase 项目，并把下面的公开配置填入 `assets/data/guestbook.data.js`。

## 1. 创建数据表

在 Supabase 项目的 **SQL Editor** 中执行：

```sql
create table public.guestbook (
  id bigint generated by default as identity primary key,
  nickname text,
  message text not null check (char_length(message) between 1 and 300),
  status text not null default 'pending' check (status in ('pending', 'approved', 'rejected')),
  created_at timestamptz not null default now()
);

alter table public.guestbook enable row level security;

create policy "Anyone can read approved echoes"
on public.guestbook for select
using (status = 'approved');

create policy "Anyone can submit pending echoes"
on public.guestbook for insert
with check (
  status = 'pending'
  and char_length(message) between 1 and 300
  and (nickname is null or char_length(nickname) <= 40)
);
```

不要创建公开的 update 或 delete policy。访客只能提交待审核留言，不能把留言直接改成已审核，也不能删除其他人的留言。

## 2. 填写公开配置

在 Supabase 的 **Project Settings → API** 中复制：

- Project URL
- `anon` / publishable key

填入：

```js
window.GUESTBOOK_CONFIG = {
  enabled: true,
  projectUrl: "https://你的项目.supabase.co",
  anonKey: "你的 anon 或 publishable key",
  table: "guestbook",
  maxLength: 300,
  pageSize: 60
};
```

这里可以出现 `anon` 或 publishable key，不能出现 `service_role` key。前端公开 key 的安全边界来自上面的 RLS policy。

## 3. 审核留言

游客提交后，留言状态是 `pending`，不会立即公开。在 Supabase 的 **Table Editor → guestbook** 中检查内容，把确认可以公开的记录改成 `approved`；不适合公开的记录改成 `rejected`。

目前留言簿不收集邮箱、IP 或地理位置，只保存昵称、留言和提交时间。

## 4. 防滥用

第一版包含字数限制和隐藏蜜罐字段，并且所有留言都需要人工审核。如果收到大量垃圾提交，再在 Supabase Edge Function 前增加 Cloudflare Turnstile；不要把 service role key 放进浏览器代码。
