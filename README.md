# 坐标之外 · Layers of Life

一个以等高线地形图为入口的个人网站，记录我的项目、音乐、日常与棒垒球经历。

我们生活在三维空间中，习惯用坐标表达「我在哪儿」，但坐标远远不能表达「我是谁」。我想把那些无法用坐标概括的经历，放在这张地图里。

**在线访问：[5644100.xyz](http://5644100.xyz/)**

## 五座山，五个入口

| 板块 | 内容 |
| --- | --- |
| 空间 | 城市空间信息工程相关的课程、科研与实习项目，包括城南古巷城市体检、深圳市便利店格局演化与驱动机制研究。 |
| 光影 | 照片与生活记录，保留原图比例，以紧凑的排布展开。 |
| 节奏 | 音乐创作、PV 与随音乐变化的可视化。 |
| 味道 | 关于食物、料理与日常的图文记录。 |
| 场 | 我的棒垒球故事、球队、比赛、俱乐部、记忆，以及一根断棒做成的挂件。 |

## 画面与交互

- 首页以统一高度场生成主体与远景的等高线，地形按平滑循环缓慢起伏；点击山峰进入对应内容。
- 地形循环在后台预计算，并通过 IndexedDB 缓存；昼夜配色与太阳光照共同构成首页的时间变化。
- 空间页使用三维城市模型承接项目，结合建筑、道路、地形和专题数据；时间维度通过时空立方体、图表与演化类型展开。
- 场页以线条风格三维棒球场作为入口，故事分布在可拖拽的空间中，断棒挂件可旋转和缩放查看。
- 各板块延续首页的绿色配色、浅深色主题与简约返回按钮，并针对手机布局和触摸操作做了适配。

## 技术

原生 HTML、CSS 与 JavaScript，无打包构建步骤，也不需要服务器端程序。地形使用 Canvas / WebGL 与 Web Worker，城市、球场和挂件的三维展示使用随仓库提供的 Three.js r128。

页面使用预处理后的地理数据和媒体资源，不需要在访问时读取原始 GIS 或 CAD 文件。三维页面需要浏览器支持 WebGL；音频与视频由用户点击播放。

## 本地浏览

克隆仓库后，在仓库根目录启动静态 HTTP 服务。例如已安装 Python 时：

```bash
git clone https://github.com/Anthony6560/layers-of-life.git
cd layers-of-life
python -m http.server 8080
```

然后打开 [http://localhost:8080](http://localhost:8080)。也可以使用编辑器的静态服务器插件。

推荐通过 HTTP 浏览，避免直接打开本地文件时的浏览器资源加载限制。网站运行不依赖 Python 或 Node.js；它们仅可用作本地服务工具。

## 维护与发布

内容入口主要位于 `assets/data/`：`site.data.js` 管理站点配置，`works.data.js` 管理作品，`moments.data.js` 管理生活记录，其他专题数据文件对应城市项目和棒垒球内容。新增媒体放入 `assets/media/` 中相应板块，并同步更新数据引用。

本仓库包含网站源码与上线所需的运行资源。原始 GIS、CAD、报告、朋友圈导出文件和离线处理工具不随仓库发布，因此这里不包含完整的数据生产流程。

站点通过 GitHub Pages 从 `main` 分支根目录发布。域名和部署步骤见 [部署说明](docs/deployment.md)。

中央盆地的“回声”是游客留言入口。留言簿使用独立的 Supabase 数据库，配置方法见 [留言簿配置](docs/guestbook-supabase.md)；没有配置数据库时，入口仍会正常显示，但提交按钮会保持关闭。
